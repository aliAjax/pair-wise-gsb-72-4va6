# 功能开关灰度发布与影响审阅平台

基于 React 的本地可运行前端工程，覆盖功能开关配置、影响评审、依赖分析、灰度时间线、冻结回滚和发布报告。业务数据由 RTK Query 端点驱动，并持久化到浏览器 `localStorage`。

## 技术栈

- React 18 + TypeScript + Vite
- MUI
- Redux Toolkit
- RTK Query
- React Router

## 启动

```bash
npm install
npm run dev
```

默认开发地址为 `http://localhost:18472`。

## 构建与自检

```bash
npm run build             # 类型检查 + 产物构建
npm run verify:snapshots  # 发布快照机制的 15 项逻辑验证（Node）
```

## 不可变发布快照模型

- **审批即固化**：每次批准生成不可变发布快照（`ReleaseSnapshot`），记录受众规则、依赖条件、回滚阈值、审批人与校验和（checksum）。开关配置后续如何修改，快照内容不变。
- **按环境独立运行**：一个发布计划覆盖 dev / staging / production 三个环境，环境只有在首次推进时才绑定快照；已推进环境始终按各自绑定的快照运行，与当前配置脱钩。
- **审批后配置更新**：保存受众、依赖、回滚阈值等受保护字段时，未推进环境的计划立即失效并回到“待评审”；已推进环境不受影响，继续按旧快照运行，报告口径同样以快照为准。
- **依赖回滚断链**：回滚某开关时，所有把它作为前置依赖（requires）的发布计划会在各自已推进环境上标注断链、停止下一阶段，需要重新审批才能解除。
- **原子写入**：快照、计划、审计事件在一次写入中落盘。写入失败时整笔拒绝，不会留下半套计划。
- **重开自愈**：读取时校验每份快照 checksum；环境绑定的快照损坏或缺失时自动回退到该开关最近一份完整快照继续运行；没有可回退快照时计划标记失效重审。

开发环境下可在浏览器控制台自检：

```js
window.__releaseDemo.failNextWrite()              // 模拟下一次保存失败
window.__releaseDemo.corruptLatestSnapshot()      // 破坏最新快照，刷新后观察自愈
```

## 工作区

- 发布概览：开关采用趋势、环境放量差异、阻断问题、依赖断链和待评审项
- 功能开关：按状态、环境、团队和关键字筛选，进入完整配置编辑器（含发布快照页）
- 影响评审：逐项检查规则冲突、死代码、指标缺失、实验重叠和客户端兼容
- 依赖关系：依赖影响图、互斥冲突矩阵、降级关系和断链告警
- 灰度发布：按环境展示绑定快照、阶段推进、冻结、断链与历史快照
- 审计与回滚：查询调整、审批、快照固化、计划失效、断链和回滚事件
- 发布报告：按各环境运行快照汇总并导出 CSV

浏览器首次打开时会自动写入示例数据（含已审批快照与多环境运行态）。编辑、审批、灰度和回滚操作会写入 `feature-flag-release-console-v1` 对应的本地存储键。
